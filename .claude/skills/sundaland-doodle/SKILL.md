# /sundaland-doodle — Gemini doodles → animated scenes

> **Channel hub:** this is one format of The Sundaland. Channel-wide constants and the format registry/rotation live in [`../sundaland/`](../sundaland/SKILL.md) (`CHANNEL.md`, `FORMATS.md`).

**Everything needed is in this skill** — prompts in `prompts/`, scripts in `template/tools/`, scene templates in
`template/scenes/`, worked examples in `template/examples/`. Past test projects under `projects/` (gitignored) are
optional reference only. The user-facing Thai walkthrough is [`FLOW_TH.md`](FLOW_TH.md).

Usage: `/sundaland-doodle <story or topic> [seconds]` — e.g. `/sundaland-doodle "a day at Laem Chabang port" 20`.

## 0. Ground rules (decided with the user — do not re-ask)

- **Reply in Thai.** On-screen captions: English (Patrick Hand font has no Thai glyphs; Thai words drawn *inside*
  the Gemini art are fine).
- **Art comes from the Gemini app, generated by the user.** The agent never calls Gemini/Imagen/Nano Banana APIs
  (`google_imagen` exists but bills the Google account — the channel allows no paid Google calls; paid TTS is ElevenLabs).
  If the user later lifts that rule, it must be an explicit decision; then use `google_imagen`
  (`generation_mode: edit`, style sheet in `image_paths`), announce model + price, sample 1 image first.
- **Never draw the cast procedurally** (SVG/ink-theater). It was tried for five rounds and never matched the
  crayon look; the user approved raster Gemini art. Procedural drawing is fine for small extras (rain, shadows).
- **Do not copy third-party stock illustrations** — the style is ours via the Gemini reference sheet.
- Narration (if any) = ElevenLabs `elevenlabs_tts`, voice **Brian** (`nPczCjzI2devNBz1zQrb`), `eleven_multilingual_v2`, per sentence, as in /sundaland-facts §3 (Google TTS Chirp3-HD only as fallback). Music = YouTube Audio Library or
  Content-ID-screened Pixabay tracks only (screen + record per track).
- **Runtime:** the templates are HyperFrames. Mention in one line that Remotion is the alternative (the facts
  format's runtime) and recommend HyperFrames for these scenes; log both in `render_runtime_selection`.
  Finished scenes are plain MP4s, so they drop into a Remotion edit as video clips.
- **Approval gates (stop and wait):** beat sheet → (user makes Gemini images) → cut-out check sheet →
  rig overlay (mocap beats only) → snapshot contact sheet → final render.

## 1. Project layout

```
projects/<slug>/
  source/      Gemini images (+ overrides.json next to a sheet if needed)
  poses/       cut-out PNGs + poses.json + _cutout-check.png
  ad/          mocap: char_<name>/, joints_<name>.json, renders/, strips
  scene/       HyperFrames composition (index.html, ink-theater.js, assets/)
```
Init the checkpoint with `pipeline_type='animation'` (doodle scenes are not a Rule-Zero manifest pipeline; still
checkpoint + decision_log the choices).

## 2. Beat sheet (first deliverable)

Write the story as beats of 1.5–4 s: caption/narration line + what the character does. For each beat choose:

| Beat needs | Path | Why |
|---|---|---|
| a specific pose/prop (laptop, umbrella, holding a box, reading) | **Sprite** (pose-swap) | any pose Gemini can draw; whole-body motion only (pop, hop, sway, slide, squash) |
| real limb motion (wave-ish greet, jump for joy, jumping jacks, dance, cheer) | **Mocap** (AnimatedDrawings) | arms/legs really move; limited to the motion catalogue (§6) |
| travel across screen | Sprite slide + hop (no leg cycle) — or a Gemini walk-frame sequence | there is no walk BVH bundled |

List the poses the user must draw (→ prompt A) and whether a rig pose is needed (→ prompt B).

## 3. Gemini images (user) → cut-outs (agent)

Give the user the prompts from [`prompts/gemini_prompts.md`](prompts/gemini_prompts.md) with the pose list filled
in, and tell them to attach `template/examples/style-reference-sheet.jpg`. When the images arrive:

```bash
python -I <skill>/template/tools/cut_poses.py projects/<slug>/source/poses-ep1.png projects/<slug>/poses coffee run read ...
```
Names are assigned **left to right**. Open `poses/_cutout-check.png` (checkerboard): background must be checks,
head/book/sign interiors solid white, and floating marks (♪, zzz, sparks, a sleeper's face) on the right figure.
Wrong owner → rerun with `--fragments` to list every small fragment (sheet coordinates + current owner), add a
box for it to `source/overrides.json` (format: `template/examples/overrides.example.json`) and rerun. Fewer groups than figures =
figures touching → ask the user for wider gaps.

## 4. Path A — sprite scene (pose-swap)

Copy `template/scenes/sprite-scene.html` → `scene/index.html`, plus `ink-theater/ink-theater.js` and
`ink-theater/assets/patrickhand.ttf` (+ `OFL.txt`) into `scene/assets/`; put the PNGs in `scene/assets/poses/`.
Edit `SIZE` from `poses.json` and rewrite the beats. Building blocks in the template:
- `actor(name, cx, k)` — travel layer > shadow + **pose** layer (pop/swap) > **idle** layer (breathe/bob/tilt) > img.
  Three layers so scale tweens never fight.
- `popIn`, `popOut`, `swap(A, B, t)`, `breathe(A, t0, t1)`, `caption(text, t0, t1)`; slides = tween `A.el` x;
  hops = yoyo `A.idle` y; shake = yoyo `#world` x; rain = seeded `.drop` divs; sign text = div inside `A.idle`.
- Line boil on the whole raster world: SVG `feTurbulence` filter stepped by `InkTheater.boil`.
- Every later `fromTo` on a target gets `immediateRender: false`; hidden starts via `gsap.set` before the timeline.

## 5. Validate & render (both paths)

```bash
npx --yes hyperframes lint projects/<slug>/scene
npx --yes hyperframes snapshot projects/<slug>/scene -o projects/<slug>/snapshots --at 1.5,4,7,10 --no-end
cd projects/<slug>/scene && npx --yes hyperframes render . -o ../<slug>.mp4 -f 30
```
Read the contact sheet before rendering; after rendering, sample 1 frame/second with ffmpeg and look again.

## 6. Path B — mocap with AnimatedDrawings (hand-rigged, no Docker)

**Setup once** (if `.tmp/animated-drawings/AnimatedDrawings/.venv` is missing): follow mode A in
`skills/creative/animated-drawing.md` (clone, `uv` Python 3.8 venv, `pip install -e .`, `setuptools<81`).
We skip the Docker auto-rig entirely: the agent places the 16 joints by eye.

1. **Pick the rig image** — the Gemini rig pose (prompt B), or the sprite whose limbs are most separated.
2. **Joints** — copy `template/examples/joints.example.json` (character's RIGHT = viewer's LEFT; sprite pixels).
   `python -I tools/check_joints.py <sprite.png>` prints the head centre and suggested `neck` + `head_circle`.
   Rules: **neck inside the head** (≈40 % of the radius below the head centre), never at the chin; shoulders at
   the torso's top corners; every joint ON the stroke.
3. **Build** — `python -I tools/prep_char.py <sprite.png> projects/<slug>/ad/char_<name> joints_<name>.json`
   (adds a 40 px pad, drops floating marks from the mesh, thickens stick limbs, cuts a moat around the head).
   Look at `char_<name>/joint_overlay.png`; then `python -I tools/check_joints.py <sprite> joints.json char_dir`
   must say *all joints inside the mesh*.
4. **Render** full-length motions (from the AD repo root, with its venv):
   `cd .tmp/animated-drawings/AnimatedDrawings && .venv/Scripts/python <skill>/template/tools/render_motions.py <char_dir> <ad>/renders dab jump jacks dance`
   (~10–30 s per motion on CPU; the `VideoWriter` warning is harmless; any *"point … not inside … mesh"* line
   means a joint is off the mesh → fix step 2).
5. **Choose windows** — `python -I tools/motion_strips.py renders/dab.mp4 strips/dab.png [start end]`, read the
   strips, write `beats.json` (example: `template/examples/beats.example.json`).
6. **Cut** — `python -I tools/cut_beats.py beats.json renders scene/assets` → prints `data-start/duration`.
7. **Compose** — copy `template/scenes/ad-scene.html`; one `<video>` per beat as a **direct child of #root** with
   its own `id`, `data-start`, `data-duration`, `data-track-index`; `mix-blend-mode: multiply` (white clip on white
   page); a small scale pop on each cut hides the pose jump between clips; last beat uses `hold`.

**Motion catalogue (bundled, verified with this cast):**

| motion | fps | frames | good windows | notes |
|---|---|---|---|---|
| `dab` (fair1) | 30 | 339 | 50–125 greet (arm up) · 230–339 cheer | best all-rounder |
| `jumping` (fair1) | 120 | 654 | 140–310 jump for joy | root motion exits frame right after ~320 |
| `jumping_jacks` (cmu1) | 30 | 125 | 10–100 | |
| `jesse_dance` (rokoko) | 100 | 1007 | 100–450 kicks | |
| `wave_hello` (fair1) | 120 | 839 | — | not a wave (hand to mouth) — avoid |
| `zombie` (fair1) | 30 | 779 | untested | |

All clips start in a T-pose — never use frames 0–~40. New motions: CMU BVH via the `ink-theater/mocap` notes,
plus a retarget config that matches the skeleton (wrong config → `'RightArm' is not in list`).

## 7. Troubleshooting (all hit during the first build)

| Symptom | Cause | Fix |
|---|---|---|
| head flattens into a dome when arms move | neck joint at the chin; head mesh webbed to upper arms | neck inside the head + `head_circle` moat (check_joints suggests both) |
| a knee/elbow never bends; log says "point … not inside … mesh" | joint off the (thin) stroke | move it onto the stroke; keep prep_char's dilation at 7 |
| faint grey rectangle around the character | clip background ≈252, not 255 | cut_beats' `colorlevels` (already in) |
| character vanishes at the end | clip shorter than the scene | `"hold": 0.6` on the last beat |
| clip frozen in the render | GIF used, or `<video>` nested in a timed div | MP4/WebM, direct child of #root |
| lint `gsap_cold_seek_hidden_fromto_missing_reveal` | fromTo reveals only in from-vars | add `opacity: 1` to the to-vars |
| captions render in a serif | webfont subset / SVG text | full `patrickhand.ttf`, HTML divs |
| sprites blurry when large | Gemini figures ~300 px tall | fewer poses per image; ≥2000 px images |
| cutter merges two figures | figures touching on the sheet | ask Gemini for wider gaps |

## 8. Into a full episode

Time beats to narration sentence timestamps (TTS per sentence, as in /sundaland-facts §3). Doodle scenes can be
standalone shorts, or MP4 inserts inside a facts episode (white background → use as full-frame cutaways or on a
white panel). End card / outro rules of the facts format still apply when it is a channel upload.

## Limits (say them honestly)
Sprite path = whole-body motion only. Mocap path = raster warp (lines stretch slightly on big moves), only the
bundled motions, no walk cycle, one rig per character (place joints per new rig image). Resolution is capped by the
Gemini image size.
